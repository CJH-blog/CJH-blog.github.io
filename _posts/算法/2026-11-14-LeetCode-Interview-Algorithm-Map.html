How This Roadmap Works

🗺️
Every interview problem belongs to a small set of patterns. Learn the pattern first, then drill representative problems — not the other way around.
1. Pick a categoryone pattern at a time, no random picking
→
2. Solve the listed problemsclick a title to open it on LeetCode
→
3. Log the solutionidea, complexity, pitfalls (template below)
→
4. Update the statusmark the problem as done in the table
→
Pattern masteredre-solve from scratch after 1 week

Status legend used in every table below: ☐ = not solved yet, ✅ = solved, 🔁 = solved once but needs a re-solve. Problem titles link directly to their LeetCode pages (open in a new tab). When I solve a problem, I append a log entry under that category's table using the template in the Solution Log Template section.

The 12 Categories at a Glance

CategoryCore ideaTypical signal in the problemPriority
Two PointersShrink the search space with two indicesSorted array, pair/triplet with a target, in-place partitionP0
Sliding WindowGrow/shrink a contiguous window, keep state insideLongest / shortest / count of substring or subarrayP0
Binary SearchHalve the space on a monotonic predicateSorted or "answer space is monotonic"P0
Hash MapTrade memory for O(1) lookups"Have I seen this before?", counting, prefix sumsP0
Linked ListPointer surgery, dummy head, fast/slowReverse, merge, detect cycle, middle nodeP0
Stack / Monotonic StackMost recent unresolved element on topMatching pairs, next greater/smaller element, histogramP1
Trees (DFS/BFS)Recursion on subtrees; queue for level orderAny nested structure with left/right childrenP0
Heap / Priority QueueAlways touch the current min/max onlyTop-K, k-th largest, streaming median, merge k sourcesP1
BacktrackingChoose → explore → un-chooseEnumerate all combinations / permutations / pathsP1
GraphsBFS / DFS / topological sort / union-findGrids, prerequisites, connectivity, shortest stepsP1
Dynamic ProgrammingOptimal substructure + overlapping subproblemsMin/max/count ways, "can it be done", sequencesP0
Greedy & IntervalsLocal optimal choice with an exchange argumentScheduling, jumping, merging, "minimum number of ..."P1

Conclusion

  1. Pattern beats problem count: 12 categories cover the vast majority of interview questions; drilling by pattern beats grinding randomly.
  2. The list is fixed, the log grows: problem tables stay as-is; solution logs accumulate under each category as problems get solved.
  3. Status is the progress bar: move problems from ☐ to ✅ (and 🔁 after spaced re-solves) — when the tables are mostly green, the roadmap is done.
